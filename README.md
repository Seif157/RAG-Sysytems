# Document RAG

Ask questions about your documents and get answers with citations back to the
page and section they came from.

Upload a PDF, DOCX, TXT or Markdown file; it is parsed, chunked, embedded and
indexed into Qdrant. Questions are answered by hybrid retrieval (dense + BM25),
reranked with a cross-encoder, and generated by an LLM that is instructed to
answer only from what it was given.

---

## Design

```
presentation  →  application  →  domain  ←  infrastructure
                                   ↑
                          core (composition root)
```

Dependencies point **inward only**. The `domain` package imports nothing but the
standard library — no framework, no vendor SDK. The rule is enforced by
`import-linter`; a violating import fails the build.

**Seven interfaces, not twenty-one.** An interface earns its place by having a
second implementation *today*: four document parsers, three chunking strategies,
several embedding and LLM providers, a no-op reranker, and in-memory doubles
that let the test suite run with no API key and no Docker. Everything else is a
plain class. Indirection that buys nothing is not architecture.

Runs as a single Streamlit process. There is no API server, no task queue, no
database — Qdrant holds the chunks and a local folder holds the originals so
re-chunking stays possible.

## Requirements

- **Python 3.12+** (developed against 3.14). The floor is real: the code uses
  PEP 695 `type` aliases and generic syntax.
- [`uv`](https://docs.astral.sh/uv/)
- Docker, for Qdrant

## Getting started

```bash
uv venv
uv pip install -e ".[dev]"
cp .env.example .env          # add OPENROUTER_API_KEY
docker compose up -d          # Qdrant
```

**One API key, and only for answer generation.** Embeddings run on your machine
by default (`BAAI/bge-small-en-v1.5`, 384 dimensions, ~130 MB, downloaded once),
so nothing is charged per document and no document text leaves the machine. Only
the LLM is hosted — set `OPENROUTER_API_KEY` from
[openrouter.ai/keys](https://openrouter.ai/keys).

Answer generation goes through OpenRouter, which fronts most vendors behind one
key and one OpenAI-compatible endpoint. Changing the answer model is therefore a
change to one variable, with no re-indexing — unlike the embedder, the LLM is
not part of the index:

```bash
LLM_MODEL=qwen/qwen3-8b                 # cheap and fast
LLM_MODEL=anthropic/claude-sonnet-4.5   # best quality
```

Talking to Google directly instead is also configuration:

```bash
LLM_PROVIDER=gemini
LLM_MODEL=gemini-2.0-flash
GOOGLE_API_KEY=...                      # aistudio.google.com/apikey
```

Moving to hosted embeddings is configuration, not code:

```bash
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSION=1536
```

Changing the embedding model invalidates the index. Start-up refuses rather than
answering from stale vectors, so drop the collection and re-upload:

```bash
curl -X DELETE http://localhost:6333/collections/document_chunks
```

Check that everything is wired correctly — this boots the system and prints what
it resolved, without starting the UI:

```bash
uv run python -m rag                   # resolved configuration
uv run python -m rag --check-store     # also create/verify the Qdrant collection
uv run python -m rag --list-settings   # every variable the system reads
```

`--check-store` is the fastest way to confirm a deployment is sound. It creates
the collection and its payload indexes if absent, and **refuses** if the
collection already holds vectors from a different embedding model — the failure
where answers look right and are wrong.

Then run it:

```bash
uv run streamlit run src/rag/presentation/ui/app.py
```

Upload a PDF, DOCX, Markdown or text file in the sidebar and ask a question.
Every answer cites the passages it used; expand a citation to see the source
text.

What each format can honestly provide differs, and the parsers say so rather
than inventing values:

| Format | Page numbers | Heading structure | Author / title |
|---|---|---|---|
| PDF | ✅ | — | ✅ |
| DOCX | — | ✅ | ✅ |
| Markdown | — | ✅ | — |
| TXT | — | — | — |

Word has no fixed pagination and Markdown has no pages, so both leave the page
number empty instead of guessing at one.

## Development

```bash
uv run pytest                                    # everything (needs Qdrant)
uv run pytest -m "not integration"               # fast, hermetic subset
uv run ruff check src tests                      # lint
uv run ruff format src tests                     # format
uv run mypy                                      # types (strict)
uv run lint-imports --config importlinter.ini    # layering contracts
```

Or `make check` to run all of them.

## Configuration

Every value the system reads lives in [`.env.example`](.env.example) and is
parsed into typed settings under `src/rag/config/`. There are no hard-coded
values, and invalid combinations fail at start-up rather than at first use —
`RERANK_TOP_K > TOP_K` and an embedding dimension that disagrees with its model
are both rejected before anything runs.

## Layout

```
src/rag/
├── presentation/    Streamlit UI — no business logic
├── application/     use cases and pipelines — orchestration
├── domain/          models, the seven ports, pure policies
├── infrastructure/  adapters: parsers, chunkers, embeddings, Qdrant, LLM
├── core/            composition root, logging, telemetry, error mapping
├── config/          typed settings
└── utils/

tests/
├── unit/            fast, hermetic
├── integration/     real Qdrant
├── architecture/    layering guards
└── fakes/           in-memory doubles
```

## Legacy prototype

`QAWithPDF/` and `StreamlitApp.py` are the original prototype, kept as a
behavioural reference and excluded from packaging and CI. They are superseded:
the upload was never actually read (`data_ingestion.py` ignored its argument and
loaded a hardcoded folder), the corpus was re-indexed on every question, and the
code no longer runs against current LlamaIndex.
