# RAG Project Summary

## Overview
This project is a simple document-based question answering application built with Streamlit, LlamaIndex, and Google Gemini. The app lets a user upload a document, process it into an index, and then ask questions about the content.

The main idea is to use Retrieval-Augmented Generation (RAG): the system loads document content, creates vector embeddings, stores the index, and then uses a Gemini language model to answer questions based on the indexed document.

---

## Main Flow
1. The Streamlit app collects the uploaded document and the user question.
2. The document is loaded from the project data folder.
3. A Gemini model is initialized.
4. The document is embedded and indexed.
5. The query engine retrieves relevant information and returns an answer.

---

## File-by-File Summary

### Root Files

- [StreamlitApp.py](StreamlitApp.py)  
  Main entry point for the UI. It creates the Streamlit app, accepts a document upload and a question, then runs the full processing pipeline and displays the answer.

- [Template.py](Template.py)  
  A small scaffolding/helper script that creates placeholder files and directories. It is not part of the main runtime logic.

- [Exception.py](Exception.py)  
  Defines a custom exception class used to wrap unexpected errors with useful context such as the file name and line number.

- [Logger.py](Logger.py)  
  Configures Python logging and creates a log file inside the [logs](logs) folder for application events and errors.

- [requirements.txt](requirements.txt)  
  Lists the Python dependencies required for the project, including Streamlit, LlamaIndex, Gemini libraries, and dotenv support.

- [setup.py](setup.py)  
  Packaging script for the project. It defines the package name, version, author, and package discovery metadata.

### Package: [QAWithPDF](QAWithPDF)

- [QAWithPDF/__init__.py](QAWithPDF/__init__.py)  
  Package initializer file. It is currently empty and marks the folder as a Python package.

- [QAWithPDF/data_ingestion.py](QAWithPDF/data_ingestion.py)  
  Responsible for loading document data from the project’s data folder. It uses LlamaIndex’s simple directory reader to read files and return document objects.

- [QAWithPDF/embeddings.py](QAWithPDF/embeddings.py)  
  Builds the vector index from the loaded documents using Gemini embeddings. It creates the query engine used for answering questions.

- [QAWithPDF/model_api.py](QAWithPDF/model_api.py)  
  Loads and configures the Gemini language model using the Google API key from the environment.

### Data and Storage

- [Data](Data)  
  Stores the source documents used by the app. The current sample file is [Data/MLDOC.txt](Data/MLDOC.txt).

- [storage](storage)  
  Contains serialized index files generated by LlamaIndex for the vector store and document store. These files help the app reuse previously built indexes.

### Experiments

- [Experiments](Experiments)  
  Contains experimental work, including a notebook for testing chat-style interactions with documents. The notebook is [Experiments/ChatWithDoc.ipynb](Experiments/ChatWithDoc.ipynb).

- [Experiments/storage](Experiments/storage)  
  Stores experiment-specific index artifacts that are separate from the main application storage.

### Logs

- [logs](logs)  
  Folder for runtime log files generated by the logging setup.

---

## What the Project Does
This project demonstrates a basic RAG workflow for asking questions over documents. It is a practical example of combining:

- document ingestion,
- embedding generation,
- vector indexing,
- model inference using Gemini,
- and a simple user interface using Streamlit.

In short, it is a lightweight document Q&A application that can answer questions from uploaded or local document content.
